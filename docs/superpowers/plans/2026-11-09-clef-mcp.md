# clef-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stdio MCP server `clef-mcp` with one tool, `decide`, that forwards a state plus named questions to Ollama's `POST /v1/systemone` and returns the answers as markdown and structured content.

**Architecture:** Mirrors `/home/mrtakdnz/projects/playground/searxng-mcp`: `config.ts` (env validation, `ConfigError`), `systemone.ts` (pure `fetch` client, response schema, error mapping), `tools.ts` (`createServer(cfg)` registering `decide`), `index.ts` (shebang, `serveStdio`, stderr-only logging). The model is never a tool input; it comes from `CLEF_MODEL`.

**Tech Stack:** TypeScript ESM, Node >=20, `@modelcontextprotocol/server` ^2.4.0, `@modelcontextprotocol/client` ^2.4.0 (dev), `zod` ^4.2.0 (`import * as z from "zod/v4"`), `vitest` ^4.0.0, `typescript` ^5.9.0, `@types/node` ^24.0.0, `shx` ^0.4.0.

**Spec:** No spec file. Requirements come from the master brief (user decisions + researched Ollama `/v1/systemone` docs at https://docs.ollama.com/api/systemone and https://docs.ollama.com/capabilities/decision). Reference implementation: `/home/mrtakdnz/projects/playground/searxng-mcp/src/*.ts`, `test/*.test.ts` (authoritative for SDK API usage).

## Review Focus

1. Choice criteria with `null` descriptions (`{"bug": null, "billing": "Charges"}`) must be accepted and forwarded unchanged. Pinned in Task 3 test `accepts choice criteria with null descriptions`.
2. Images passed as data URLs or http URLs must be rejected before any fetch, with a message naming base64. Pinned in Task 3 test `rejects data URL and http URL images before calling fetch`.
3. Non-JSON upstream error bodies (HTML 502 from a proxy) must yield `Ollama returned HTTP 502: <excerpt>`, not a crash. Pinned in Task 2 test `uses a body excerpt when the error body is not JSON`.
4. The API key must never leak into error text (401, network failure, timeout). Pinned in Task 2 test `never includes the API key in error messages` and Task 1 test `never includes the API key in ConfigError messages`.
5. `CLEF_BASE_URL` with a trailing slash or a path prefix (`http://host:8080/ollama/`) must hit `http://host:8080/ollama/v1/systemone`. Pinned in Task 1 test `normalizes trailing slashes and keeps a path prefix` and Task 2 test `posts to {base}/v1/systemone`.

**Exact copy:**

`SERVER_INSTRUCTIONS`:
```
clef-mcp exposes one tool, decide, backed by Ollama's /v1/systemone decision endpoint. Use it when you need a fast, probability-calibrated judgement about a piece of text, JSON data, or images: pick one label (choice), estimate how likely a yes/no statement is true (noul), or grade on an ordered scale (score). Batch every question about the same state into one call. The model is fixed by the server configuration and cannot be chosen per call.
```

`DECIDE_DESCRIPTION`:
```
Ask an Ollama decision model to answer one or more structured questions about a state, in a single call. Answers are probabilities, never free text, so you can threshold them.

Inputs:
- state: what to judge. Non-empty text, or a JSON object or array (sent as JSON text).
- questions: map of question name to question. 1 to 64 questions. Names are 1-100 characters of ASCII letters, digits, "_", "." or "-".
- images (optional): up to 4 images as raw base64 strings (no data: URLs, no http URLs).

Every question has a type, instructions (text, or a JSON object or array, explaining what to decide) and criteria:
- choice: pick exactly one label. criteria is required: an object mapping 2-26 label keys to a description string or null. Answer: choice (the winning key), probabilities (one per key, summing to 1) and confidence (0-1).
- noul: a yes/no judgement. criteria is optional: exactly {"false": "...", "true": "..."} describing each side. Answer: noul, the probability from 0 to 1 that the statement is true. It is not a boolean and has no confidence field.
- score: place the state on an ordered scale. criteria is required: an array of 2-10 level descriptions ordered from lowest to highest. Answer: score, the probability-weighted mean of the zero-based level index (for example 1.84 on a 0-2 scale; not rounded), legend (index to description), probabilities (per index) and confidence (0-1).

Use it for classification, routing, triage, moderation and rubric grading. Do not use it to generate text.
```

**Markdown format** (`renderDecisionMarkdown`): one block per answer in `answers` order, numbers via `Number(x.toFixed(3))`:
- choice: `**label** (choice): bug, confidence 0.891` then `  probabilities: bug 0.978, billing 0.013, account 0.009` (sorted by probability, descending)
- noul: `**refund** (noul): 0.97 probability that the statement is true`
- score: `**urgency** (score): 1.84 on a 0-2 scale, closest level 2 "Immediate: a critical service is unavailable", confidence 0.71` (closest level = `Math.round(score)` clamped to legend range; max index = legend size - 1)
- last line: `Usage: 174 input tokens, 1 output tokens`

## Assumptions

- Server description is delivered as MCP `instructions` (`ServerOptions.instructions`, verified in `@modelcontextprotocol/server` typings; `Client.getInstructions()` exists). `package.json` `description` holds a one-line summary.
- Cloud-only limits (name regex, max 4 images) are enforced for local servers too; simpler and keeps one schema.
- Choice criteria cap is 26 (docs page), not 255 (spec).
- `CLEF_TIMEOUT_MS` added because searxng-mcp has `SEARXNG_TIMEOUT_MS`; default 60000 ms chosen because model scoring is slower than search.
- Integration test is gated on a dedicated `CLEF_INTEGRATION_BASE_URL` (mirrors `SEARXNG_INTEGRATION_URL`), not on `CLEF_API_KEY`, so a key already in the shell never triggers paid calls during `npm test`.
- `npm test` includes `test/e2e.test.ts`, which requires `dist/` (same as searxng-mcp), so full runs build first.
